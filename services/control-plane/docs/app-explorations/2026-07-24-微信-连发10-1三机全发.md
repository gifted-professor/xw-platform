## 感知与输入链路

- UI hierarchy 能读到什么: 仅约 382 字节空 root XML，不能读取微信节点。
- Flutter/WebView 缺失什么: 页面标题、会话行、搜索结果、按钮语义和 bounds。
- OCR/vision: 全程使用 vision_analyze 截图分析；坐标系统性偏移约 550px（4号机实测），需逐设备校准。
- 文字输入方式:
  - 数字/英文: `adb_shell input text` ✅ 可用
  - 中文: 效卫 IME `inputText` 返回 SUCCESS 但实际不落字 ❌
  - `keyevent` 逐位落字: `'0'→7, '1'→8, ..., '9'→16` ✅ 验证通过
- 焦点/InputConnection 验证: 输入框有光标 → `input text` 可落字。
- 文本真实落字验证: vision 确认输入框出现文字。
- IME 恢复验证: 收尾时保持 XwIME，未切换。
- **发送按钮定位**:
  - `keyevent 66` (Enter) → 打开表情面板，不发送
  - `input tap (994, 2150)` → 点到表情按钮
  - `input tap (1060, 2150)` → **发送成功** ✅
  - `find-send-btn` 按钮消失法: 发送后按钮位置变空 → 回验成功

## 候选能力卡

### `wechat.message.send`

- `actionId`: `wechat.message.send`
- 成熟度: **`E2 repeatable`**（07-22 为 `E0_not_live_certified`）
- `precondition`: 设备在线；微信已登录；已在目标聊天页面；输入框可聚焦
- `params`: `deviceAlias`、`chatTitle`、`messageText`
- `executor`: `adb_shell input tap`（输入框）+ `adb_shell input text`（落字）+ `adb_shell input tap`（发送按钮）
- `postcondition`: 消息出现在聊天记录中；输入框清空
- `risk`: 中；发送按钮坐标需逐设备校准
- `cleanup`: 返回主消息页
- `knownFailures`: 发送按钮坐标偏移；输入框未获焦；旧消息污染
- 可自动恢复: MOVE_END + 24×DEL 清草稿
- 必须 fail-closed: 发送后按钮未消失、输入框未清空、新气泡未出现

### `wechat.conversation.open`

- `actionId`: `wechat.conversation.open`
- 成熟度: `E1 one-off`（仅 01 号机通过结构化 API 验证）
- `precondition`: 设备在线；微信已登录；当前在主消息页
- `params`: `deviceAlias`、`contactName`
- `executor`: 结构化 API（01）或手动搜索+点击（其他设备）
- `postcondition`: 聊天页面顶部标题匹配
- `risk`: **高**；搜索页 input tap 不响应
- `cleanup`: 返回主消息页
- `knownFailures`: 搜索页 input tap 穿透；vision 坐标偏移；效卫 IME 不落字
- 可自动恢复: 按返回栈退回主消息页
- 必须 fail-closed: 标题不匹配、搜索结果为空、出现风控页

## 尚未验证的边界

- **幂等/防双发**: 同一 idempotencyKey 成功后只返回缓存结果 — 未真机验证
- **无人值守发送**: 全部 10/10 为人工门禁确认，非自动化
- **发送气泡回验**: 新气泡数量增加 — 部分验证，未做 SHA-256 对比
- **超时 ambiguous 处理**: 发送后新气泡无法确认时的状态锁定 — 未验证
- **搜索结果滚动/分页**: 多结果时的精确定位 — 未验证
- **重名联系人**: 同名联系人/群聊的区分 — 未验证
- **中文消息发送**: 全部为数字消息，中文发送未验证
- **图片/文件/语音消息**: 仅验证文本消息
- **WeChat 结构化 API 多设备**: 仅 01 号机可用，其他设备需手动操作
- **微信版本升级兼容性**: 8.0.64 以上版本未测试
